## 1. 文档目的

本文定义公司内部 RAG 知识库平台的产品需求，用于指导产品设计、研发、测试、部署和验收。

平台参考 RAGFlow 的数据集管理、文档解析、可干预分块、混合检索、重排序、元数据过滤、检索测试和来源引用等能力，但不照搬 RAGFlow 的全部功能。

本期建设重点是：提供稳定、可追溯、可评估、具备权限控制的企业级 RAG 服务。

## 2. 项目背景

公司当前缺少统一的 RAG 数据处理和知识检索能力，主要存在以下问题：

1. 文档分散在不同目录或系统中，无法统一管理。
2. 各业务项目重复实现文件解析、分块、Embedding 和检索逻辑。
3. 不同项目的检索参数和结果格式不一致，难以复用和评估。
4. 检索结果缺少页码、文档和内容块定位，无法可靠追溯来源。
5. 文档更新或删除后，旧索引可能继续被检索，存在数据一致性风险。
6. 缺少知识库权限控制，调用方可能访问超出授权范围的数据。
7. 缺少检索测试、指标和调用链追踪，结果不好时无法判断是解析、分块、召回还是排序问题。

## 3. 产品定位与边界

### 3.1 产品定位

RAG Base 是统一的企业 RAG 平台，负责：

- 知识库、文档和元数据管理；
- 文档解析、清洗、分块、Embedding 和索引；
- 关键词、向量和混合检索；
- 可选重排序和元数据过滤；
- 返回可被上层应用使用的知识内容块；
- 返回文档、页码、位置和稳定引用信息；
- 提供检索测试、质量评估和运行追踪；
- 通过 HTTP API、MCP Server 和 LangChain/LangGraph 适配提供统一检索能力。

### 3.2 系统职责边界

| 领域 | 本项目负责 | 本项目不负责 |
| --- | --- | --- |
| 数据管理 | 知识库、文档、版本、元数据和权限 | 外部业务数据的生产流程 |
| 数据处理 | 解析、清洗、分块、Embedding 和索引 | 原始业务数据的人工编写 |
| 检索 | 关键词、向量、混合检索、过滤和重排序 | 业务问题理解和多轮交互 |
| 结果 | 返回内容块、得分、元数据和引用 | 基于内容生成最终业务答案 |
| 质量 | 检索调试、离线评测和运行追踪 | 上层应用的业务效果评估 |
| 接口 | HTTP API、MCP、鉴权和 LangChain/LangGraph 适配 | 上层应用页面及业务流程 |

### 3.3 MVP 非目标

本期不建设：

- 聊天界面、问答机器人或会话管理；
- 工作流编排、工具市场和业务动作执行；
- 自研大模型训练平台；
- 向量数据库或搜索引擎本身；
- GraphRAG、知识图谱和 RAPTOR；
- 互联网搜索；
- 长期记忆、用户画像和会话记忆；
- LLM 最终答案生成或业务结论生成；
- Chat Completions 兼容接口；
- 计费、套餐、支付和发票系统。

### 3.4 已确定技术约束

- 后端应用框架采用 FastAPI。
- HTTP 接口采用 JSON REST API；对外检索 API 与管理前端私有 API 分别通过 FastAPI 生成 OpenAPI 文档。
- MCP 冻结使用 `2026-07-28` 协议版本，采用无状态 Streamable HTTP 传输，不新增已废弃的 HTTP+SSE 传输实现。
- MCP `2026-07-28` 不要求 `initialize`、`initialized` 或会话 ID；客户端可直接调用 `tools/list`、`tools/call`，需要能力发现时使用 `server/discover`。
- MCP 网关校验 `Mcp-Protocol-Version`、`Mcp-Method`、`Mcp-Name`，并校验请求 `_meta` 中的协议版本、客户端信息和能力声明。旧版 MCP 如需兼容，应使用独立入口，不得与 MVP 端点混用生命周期语义。
- HTTP 与 MCP 复用同一鉴权、权限校验、检索服务和结果映射，不维护两套检索逻辑。
- 首批调用项目使用 LangChain 和 LangGraph，平台提供对应 Python 适配组件。
- LangChain/LangGraph 只作为调用端集成依赖，不进入核心检索服务的必需依赖。
- 内部 RAG 组件框架采用开源版 LlamaIndex，仅用于 Loader、Node Parser、Transform 和 Ingestion Pipeline 编排。
- LlamaIndex 必须封装在平台内部适配层之后；账号权限、文档版本、索引发布、Elasticsearch/pgvector 混合检索、Rerank、审计和 API 契约由 RAG Base 自身控制。
- 核心能力不得依赖 LlamaCloud、LlamaParse 云服务或其他 LlamaIndex 公网托管服务。
- 耗时入库任务不得在 FastAPI 请求进程内同步执行，应交由异步任务执行单元处理。
- 文档原文件和受保护预览统一使用七牛云对象存储 Kodo 私有空间；服务端通过官方 Python SDK 使用 HTTPS 访问，预览和下载使用短期有效下载凭证。
- FastAPI、任务执行单元、PostgreSQL/pgvector、Elasticsearch、模型服务、解析内容、索引、账号、日志和密钥采用公司环境内私有化部署。
- 上传文档的原文件及受保护预览统一存储到公司七牛云账号下的对象存储 Kodo 私有空间；不得使用公开空间或永久公开 URL。
- 七牛云对象存储是 MVP 唯一允许承载文档原文件和预览的公网托管数据服务；解析文本、内容块、向量、倒排索引、查询和模型输入输出不得因此发送到七牛云。
- 私有化环境允许并需要受控访问外网，但系统服务不要求直接暴露在公网。
- Embedding 模型固定使用 `BAAI/bge-m3`，Rerank 模型固定使用 `BAAI/bge-reranker-v2-m3`。
- Embedding 与 Rerank 推理服务均在公司私有化环境本地部署，核心检索链路不调用外部模型 API。
- 全文搜索引擎采用 Elasticsearch，负责关键词召回、倒排索引和命中高亮。
- 关系数据库采用 PostgreSQL，向量存储与向量检索采用 pgvector 扩展；Elasticsearch 不作为主向量库。
- HTTP 与 MCP 同时开放关键词、向量和混合三种检索模式，并使用同一组检索调用参数、默认值和取值范围。
- 开发前必须冻结 Python、FastAPI、PostgreSQL、pgvector、Elasticsearch、IK、LlamaIndex、BGE 推理服务、MCP SDK、LangChain 和 LangGraph 的精确版本、容器镜像摘要和依赖锁文件；生产禁止使用 `latest` 标签。
- IK 插件版本必须与 Elasticsearch 版本严格匹配；正式开发前完成 MCP `2026-07-28`、LangChain/LangGraph 和 FastAPI 的最小兼容性验证。

## 4. 项目目标与成功指标

### 4.1 项目目标

1. 建立统一的企业知识库管理和检索能力。
2. 上层应用可通过 HTTP 或 MCP 检索一个或多个授权知识库。
3. 每条检索结果都可追溯到知识库、文档、页码和内容块。
4. 支持在不修改上层应用的情况下调整召回、融合和排序策略。
5. 文档上传、更新、停用和删除能够正确反映到检索结果。
6. 建立可重复的检索质量评估方法，而不是依赖人工演示判断效果。

### 4.2 MVP 成功指标

| 指标 | 验收目标 |
| --- | --- |
| API 接入 | 至少一个真实业务调用方在测试环境完成端到端接入 |
| 协议一致性 | 相同账号、查询和参数通过 HTTP/MCP 返回相同排序语义和引用信息 |
| 框架接入 | LangChain 与 LangGraph 均完成同步及异步真实调用验证 |
| 数据权限 | 0 个可复现的跨知识库、跨文档越权检索问题 |
| 引用完整率 | 有效检索结果 100% 带文档和稳定块标识；有页码的文档必须带原始页码 |
| 索引一致性 | 已停用或删除文档在承诺时间内不再出现在新检索结果中 |
| 检索可解释性 | 每次检索可查看召回来源、各阶段得分、过滤原因和耗时 |
| 检索质量 | 不少于 100 个真实问题；Recall@10 不低于 0.80、MRR@10 不低于 0.60，权限泄露用例 100% 通过 |
| 接口稳定性 | 完成可复现的性能与稳定性基线测试；业务目标确认前不设置数值型上线门槛 |
| 任务可追踪性 | 100% 导入任务具有唯一编号、状态、参数版本和错误记录 |

## 6. 核心术语

| 术语 | 定义 |
| --- | --- |
| 知识库 | 具有统一权限、解析策略和 Embedding 空间的一组文档；在线检索使用平台已发布配置 |
| 文档 | 上传或同步到知识库的原始资料及其元数据 |
| 内容块（Chunk） | 文档经过解析和切分后用于索引、检索和引用的最小业务单元 |
| 父子块 | 使用较小子块进行匹配，命中后返回包含更多上下文的父块 |
| Embedding | 将文本转换为向量表示的过程或模型 |
| 关键词检索 | 基于词项相关度的检索能力，例如 BM25 |
| 向量检索 | 基于查询向量和内容块向量相似度的检索能力 |
| 混合检索 | 同时使用关键词和向量召回，并将结果融合排序 |
| Rerank | 使用重排序模型对候选内容块重新计算相关性顺序 |
| 引用（Citation） | 标识来源文档、页码及内容块位置的可追溯信息 |
| 检索追踪 | 一次检索请求从权限过滤、召回、融合到返回结果的完整记录 |

## 7. 典型使用场景

### 7.1 企业制度检索

业务系统提交制度查询和允许访问的知识库范围。RAG Base 完成权限校验，返回相关制度内容、得分和页码引用，不生成最终答案。

### 7.2 产品资料更新

知识运营人员上传新版产品手册，预览解析和分块结果，确认后发布索引。旧版本文档被停用，新请求只能检索到已发布的新版本，历史检索记录仍保留版本信息。

### 7.3 多知识库检索

调用方同时检索产品手册、售后政策和常见问题知识库。RAG Base 校验调用账号对每个知识库的权限，再执行混合检索和统一排序，返回去重后的结果。

### 7.4 检索效果调试

评测人员输入问题，查看关键词召回、向量召回、融合得分和重排序结果，使用不同检索参数进行对比测试；测试不会修改其他调用方的请求参数。

### 7.5 文档删除

运营人员删除包含过期或敏感信息的文档。系统立即阻止新访问，并异步清理对象文件、内容块和索引；清理完成前，检索层也必须通过状态过滤保证文档不再返回。

### 7.6 LangChain/LangGraph 检索

LangChain 项目通过标准 Retriever 获取 `Document` 列表；LangGraph 项目通过检索节点或 MCP 工具查询知识库。两种方式返回相同的内容块、得分、元数据和引用信息。

## 8. 业务流程

### 8.1 知识入库流程

```text
创建知识库
   ↓
查看固定 Embedding 信息，配置解析和分块策略
   ↓
上传文档并填写元数据
   ↓
文件校验 → 解析 → 清洗 → 分块 → Embedding → 写入索引
   ↓
预览内容块并进行检索测试
   ↓
发布文档
   ↓
允许在线检索
```

### 8.2 在线检索流程

```text
调用方提交检索查询
   ↓
请求携带知识库和业务过滤条件
   ↓
RAG Base 注入平台固定租户标识，并校验调用账号与知识库权限
   ↓
关键词召回 + 向量召回
   ↓
融合 → 可选 Rerank → 阈值过滤 → 去重
   ↓
返回内容块、得分、元数据和引用
```

### 8.3 知识库、文档与索引状态

知识库状态固定为：

| 状态 | 含义 | 能否检索 |
| --- | --- | --- |
| `DRAFT` | 已创建但尚未启用 | 否 |
| `ACTIVE` | 已启用，可检索其中已发布内容 | 是 |
| `DISABLED` | 已停用 | 否 |
| `DELETING` | 正在删除 | 否 |
| `DELETED` | 已完成删除 | 否 |

`Document` 作为稳定的业务文档身份；状态由 `DocumentVersion` 承载：

| 状态 | 含义 | 能否检索 |
| --- | --- | --- |
| `UPLOADED` | 文件已上传，尚未开始处理 | 否 |
| `PROCESSING` | 正在解析、分块或建立索引 | 否 |
| `REVIEW_REQUIRED` | 处理完成，等待人工确认 | 否 |
| `PUBLISHED` | 已发布且索引可用 | 是 |
| `FAILED` | 入库失败 | 否 |
| `DISABLED` | 已停用 | 否 |
| `DELETING` | 正在删除原文和索引 | 否 |
| `DELETED` | 已完成删除 | 否 |

同一文档最多只能有一个 `PUBLISHED` 版本，该约束必须由数据库保证。只有处于 `ACTIVE` 知识库内的 `PUBLISHED` 文档版本可以参与在线检索，状态变化必须写入审计记录。

`IndexVersion` 归属于知识库，每个知识库只维护一个 `active_index_version`。新版本必须先在 Elasticsearch 和 pgvector 中完整构建并校验，再通过数据库事务切换活动版本；切换失败继续使用上一版本，旧索引保留到异步清理完成。

允许的核心状态迁移如下，未列出的迁移一律拒绝：

| 对象 | 允许的状态迁移 |
| --- | --- |
| KnowledgeBase | `DRAFT -> ACTIVE`；`ACTIVE <-> DISABLED`；`DRAFT/ACTIVE/DISABLED -> DELETING -> DELETED` |
| DocumentVersion | `UPLOADED -> PROCESSING`；`PROCESSING -> REVIEW_REQUIRED/FAILED`；`FAILED -> PROCESSING/DELETING`；`REVIEW_REQUIRED -> PUBLISHED/DELETING`；`PUBLISHED -> DISABLED/DELETING`；`DISABLED -> PUBLISHED/DELETING`；`DELETING -> DELETED` |
| IndexVersion | `BUILDING -> READY/FAILED`；`FAILED -> BUILDING/DELETED`；`READY -> ACTIVE/DELETED`；`ACTIVE -> RETIRED`；`RETIRED -> ACTIVE/DELETED` |

发布新文档版本时，新版本进入 `PUBLISHED` 与旧版本进入 `DISABLED` 必须在同一事务语义内完成；回滚仅允许在目标版本及其双索引均完整可用时执行。

## 10. 功能需求

### 10.1 身份与权限（MVP 单租户）

#### FR-AUTH-001 登录与服务认证

- 本平台建立独立账号体系，不依赖公司现有 IAM、SSO 或其他业务系统账号。
- MVP 采用单租户模式，不提供租户创建、切换、租户管理员或租户停用功能。
- 人工账号使用邮箱和密码登录管理界面，邮箱作为平台内唯一登录名。
- 邮箱唯一性按忽略大小写和首尾空格后的规范值判断；登录时同样按规范值匹配。
- 平台不开放匿名访问；MVP 默认不开放自助注册，账号由平台账号管理员创建。
- 密码只保存安全哈希，禁止明文存储、记录日志或通过接口返回。
- 密码默认不少于 12 个字符，密码策略可由平台管理员配置。
- 登录成功后签发具有有效期的访问凭证；退出、禁用账号或管理员强制下线后，凭证必须失效。
- 连续登录失败需要限流和临时锁定，错误提示不得暴露账号是否存在。
- 首次部署通过安全的初始化流程创建唯一初始平台管理员，不得内置通用默认密码。
- 初始平台管理员账号由业务团队指定人员保管，创建、交接、重置和停用均需审计。

#### FR-AUTH-002 访问范围校验

- 在线检索校验平台固定租户标识、API 调用账号和知识库授权范围。
- API Key 只能访问“自身授权范围”与“所属调用账号当前授权范围”的交集，客户端参数不能扩大权限范围。
- 一次请求包含多个知识库时，只要其中任一编号不存在或不在账号授权范围内，整次请求返回 `403 FORBIDDEN_SCOPE`，不执行任何检索。
- 权限错误不得返回具体失败的知识库编号，也不得透露目标是否存在；不允许部分成功或静默缩小检索范围。
- 越权请求不得泄露知识库、文档或内容块是否存在。

#### FR-AUTH-003 权限模型

MVP 全局角色仅包括：

- `PLATFORM_ADMIN`：平台配置、模型运行状态、节点、配额和运维管理；不自动获得知识库内容读取权限；
- `ACCOUNT_ADMIN`：人工账号和 API 调用账号生命周期管理；不自动获得知识库内容读取权限；
- `USER`：可登录平台，具体知识库能力由直接授权决定。

MVP 支持以下知识库权限：

- 管理：修改配置、权限和删除知识库；
- 编辑：上传、更新、发布、停用文档，编辑内容块；
- 检索：通过 UI 或 API 检索已发布内容；
- 评测：创建测试集和查看评测结果。

人工账号和 API 调用账号由本平台与知识库建立直接授权关系。MVP 不支持用户组、部门或组织层级继承授权。知识库权限变更需在 5 分钟内对新请求生效。
MVP 中 API 调用账号只允许获得“检索”权限，不允许登录管理界面或执行知识库管理操作。
“知识库管理员”不是全局角色，指拥有目标知识库 `MANAGE` 权限的人工账号。初始管理员同时拥有 `PLATFORM_ADMIN` 和 `ACCOUNT_ADMIN`；创建知识库的人工账号自动获得该知识库 `MANAGE`、`EDIT`、`RETRIEVE`、`EVALUATE` 四项权限。

全局角色能力矩阵：

| 平台能力 | `PLATFORM_ADMIN` | `ACCOUNT_ADMIN` | `USER` |
| --- | --- | --- | --- |
| 平台配置、模型运行状态、节点和配额 | 允许 | 拒绝 | 拒绝 |
| 人工账号/API 调用账号生命周期 | 拒绝，除非同时持有 `ACCOUNT_ADMIN` | 允许 | 拒绝 |
| 创建知识库 | 拒绝，除非同时持有 `USER` | 拒绝，除非同时持有 `USER` | 允许 |
| 读取知识库正文和检索结果 | 仅有直接知识库授权时允许 | 仅有直接知识库授权时允许 | 仅有直接知识库授权时允许 |

知识库权限矩阵：

| 权限 | 允许操作 |
| --- | --- |
| `MANAGE` | 修改知识库配置、管理直接授权、启停和删除知识库 |
| `EDIT` | 上传、解析、发布、停用和删除文档，编辑或停用内容块 |
| `RETRIEVE` | 检索已发布内容，读取有权限的内容块和引用来源 |
| `EVALUATE` | 管理评测集、执行检索测试和查看评测结果 |

#### FR-AUTH-004 人工账号生命周期

- 平台账号管理员可以创建、查询、编辑、禁用和恢复人工账号。
- 人工账号至少包含登录邮箱、显示名称、平台角色、状态、创建时间和最后登录时间。
- 账号状态包括 `ACTIVE`、`LOCKED`、`DISABLED`；只有 `ACTIVE` 可以登录。
- 管理员可发起密码重置；重置后的临时密码首次登录必须修改。
- 用户可修改自己的密码；修改密码后已有会话按安全策略全部失效。
- 账号不得物理删除以破坏历史审计关系；离职或停用使用 `DISABLED` 状态。
- 禁用人工账号后，其当前会话立即失效。

#### FR-AUTH-005 API 调用账号与 API Key

- API 调用账号是独立于人工账号的非登录主体，只能用于调用 HTTP API 或 MCP Server。
- API 调用账号至少包含名称、用途、负责人、状态、授权知识库、创建时间和最后调用时间。
- API 调用账号状态包括 `ACTIVE`、`DISABLED`；禁用后其全部 API Key 立即失效。
- 一个 API 调用账号可以创建多个 API Key，以支持灰度轮换和不同部署环境。
- API Key 只在创建时完整展示一次，服务端仅保存不可逆摘要或安全等价物。
- API Key 包含名称、所属调用账号、知识库范围、创建时间、最后使用时间和状态，不设置过期时间。
- API Key 永久有效，直至被管理员主动禁用、删除，或所属 API 调用账号被禁用；平台不得因存续时间自动使其失效。
- 单个 API Key 的权限范围不得超过所属 API 调用账号的授权范围。
- 支持创建、禁用、删除和轮换 API Key；密钥轮换不得要求业务系统停机。
- API Key 和知识库授权的创建、变更、禁用均写入审计日志。

#### FR-AUTH-006 账号与知识库授权管理

- 持有知识库 `MANAGE` 权限的人工账号可以在本人管理的知识库中授权人工账号或 API 调用账号。
- 每条授权记录必须直接关联一个人工账号或 API 调用账号与一个知识库，不通过用户组、部门或组织节点间接授权。
- MVP 不建设用户组管理、用户组成员关系、用户组批量授权和组织层级权限继承。
- 平台账号管理员负责账号生命周期，但不因此自动获得全部知识库正文读取权限。
- 授权记录包含主体类型、主体编号、知识库编号、权限集合、授权人、生效时间和失效时间。
- 同一主体对同一知识库的重复授权需合并或拒绝，不得产生语义冲突的多条有效记录。
- 撤销授权后，新的管理请求和检索请求立即或在 5 分钟内失效；缓存不得长期保留旧权限。
- 系统提供按账号查看知识库权限、按知识库查看已授权账号两种视图。

### 10.2 知识库管理

#### FR-KB-001 创建知识库

- 知识库名称在整个平台内唯一。
- 创建时填写名称、描述、默认语言、分块策略和权限范围；Embedding 模型使用平台固定的 `BAAI/bge-m3`，不由普通用户选择。
- 系统生成不可预测的知识库编号。
- 创建成功后知识库状态为 `DRAFT`，创建人自动获得 `MANAGE`、`EDIT`、`RETRIEVE`、`EVALUATE` 四项直接权限；不包含已发布文档时不得返回检索结果。

#### FR-KB-002 Embedding 模型约束

- MVP 的 Embedding 模型固定为 `BAAI/bge-m3`，使用其 1024 维稠密向量能力完成向量检索。
- 一个知识库内所有已发布内容块必须使用同一 Embedding 模型及向量维度。
- 知识库已有索引后，不允许直接修改 Embedding 模型。
- 更换模型必须创建重建任务，在新索引完整、校验通过后原子切换。
- 重建失败时继续使用旧索引，不得使线上知识库不可用。
- 每个内容块记录 Embedding 模型、版本和模型文件校验值。

#### FR-KB-003 删除知识库

- 删除前必须二次确认，并展示文档数、内容块数和已授权 API Key 数量。
- 删除后立即禁止新检索，异步清理文件、向量、倒排索引和缓存。
- 删除任务必须可追踪、可重试，不能只删除数据库主记录。
- 知识库删除审计日志永久保存，但不得通过审计日志保留已删除的文档正文和向量。

### 10.3 文档管理

#### FR-DOC-001 文件上传

- MVP 主要处理中文文档，同时不得破坏文档中已有的英文、数字和业务代码。
- MVP 固定支持以下格式：PDF、DOCX、XLSX、PPTX、TXT、MD、HTML、CSV、JSON、EML、PNG、JPG/JPEG。
- 不再以 RAGFlow 支持格式作为 MVP 承诺范围；DOC、XLS、PPT、BMP、TIF/TIFF、音频、视频及其他格式进入后续版本评估。
- 项目建立《支持格式矩阵》，逐项记录扩展名、MIME、解析器、文件限制、是否 OCR 和验收样例。
- 支持管理前端拖拽和文件选择；文件通过 `/internal/api/v1/...` 私有管理接口上传，不作为外部集成能力开放。
- 支持批量上传；单个文件失败不影响同批其他文件。
- 默认单文件上限 200 MB，管理员可配置。
- 单文件解压后内容默认不得超过 1 GB；PDF 默认最多 2,000 页，PPTX 默认最多 1,000 张幻灯片，XLSX 默认最多 100 个可见工作表且非空单元格总数不超过 1,000,000，EML 默认最多处理 100 个附件。超限时整体拒绝并返回稳定错误码，限制可由平台管理员下调。
- 服务端校验扩展名、MIME、文件特征、大小和空文件。
- 文件名只用于展示，实际存储键不得直接使用用户文件名。

#### FR-DOC-002 文档元数据

文档支持系统元数据、业务元数据和权限元数据：

- 系统字段：文档编号、原文件名、格式、大小、校验值、版本、创建人、更新时间、状态；
- 自定义字段：持有知识库 `MANAGE` 权限的人工账号预先定义名称、类型、是否必填、是否可用于过滤、是否允许内容块覆盖。

元数据类型至少支持字符串、数字、布尔、日期和字符串列表。参与过滤的字段必须建立可用索引。

平台提供可选的 K12 业务元数据模板。选择该模板的知识库包含以下预置字段；其他知识库可以不启用该模板，并按自身业务定义元数据 Schema。

| 字段 | 示例/类型 | 用途 |
| --- | --- | --- |
| `content_type` | `PRICE`、`SCHEDULE`、`SALES_SCRIPT` | 区分价格、班期、销售话术等内容类型 |
| `course_id` | `MATH_G7` | 限定具体课程 |
| `grade_code` | `G7` | 按年级过滤 |
| `subject_code` | `MATH` | 按学科过滤 |
| `campus_id` | `SH_PUDONG` | 区分不同校区的价格、班期等内容 |
| `term_code` | `2026_AUTUMN` | 按学期过滤 |
| `class_type` | `ONLINE`、`OFFLINE` | 区分线上班和线下班 |
| `valid_from` | `TIMESTAMPTZ/NULL` | 可空；`NULL` 表示立即生效 |
| `valid_to` | `TIMESTAMPTZ/NULL` | 可空；`NULL` 表示长期有效 |
| `sales_stage` | `FIRST_CONTACT`、`FOLLOW_UP` | 选择对应销售阶段的话术 |
| `channel` | `WECOM`、`PHONE` | 选择适合企业微信或电话等渠道的话术 |
| `tags` | 字符串列表，如 `优惠异议`、`价格敏感` | 辅助检索和话术筛选 |

首期权限元数据如下：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `tenant_id` | `UUIDv7` | 平台内部固定的单租户标识，由服务端生成并在所有检索中强制过滤，调用方不得传入或修改 |
| `knowledge_base_id` | `UUIDv7` | 限定调用账号已获授权的知识库 |
| `document_id` | `UUIDv7` | 指定文档并追溯来源 |
| `document_version` | `INTEGER` | 只检索当前发布版本 |
| `index_version` | `INTEGER` | 防止新旧索引混用 |
| `document_status` | `ENUM` | 只允许 `PUBLISHED` 文档参与检索 |
| `chunk_enabled` | `BOOLEAN` | 排除人工停用的内容块 |

- 业务元数据由知识运营人员填写或通过私有管理接口提交，并按知识库定义进行枚举、格式和必填校验。
- 权限元数据由平台根据固定租户标识、知识库授权、文档状态和内容块状态生成，调用方不得直接写入或覆盖。
- `valid_from`、`valid_to` 均可为空并统一按 UTC 存储和比较；有效区间采用左闭右开 `[valid_from, valid_to)`。MVP 不提供历史时间点检索。
- MVP 不支持部门级内容隔离和内容密级过滤，`department_ids`、`security_level` 不进入 MVP 数据模型、接口或检索条件。
- 每个知识库维护版本化元数据 Schema。字段成为索引字段后类型不得原地修改；类型变化必须新建字段并重建索引。
- 删除字段应先标记为 `DISABLED`；历史文档版本保留原值，完成索引重建和清理后才能物理删除字段定义。
- 文档级元数据默认继承到内容块；只有标记为 `chunk_overridable` 的字段允许块级覆盖，存在覆盖值时以内容块值为准。

#### FR-DOC-003 文档版本

- 同一业务文档上传新文件时可创建新版本。
- 新版本在解析和审核期间不影响当前已发布版本。
- 发布新版本时原子停用旧版本并启用新版本。
- 历史检索追踪继续指向当时命中的具体版本。
- 默认只允许最新已发布版本参与检索。
- 同一文档最多存在一个 `PUBLISHED` 版本，数据库必须使用唯一约束或等价事务约束保证。
- 新版本记录 `source_version_id`、变更类型和变更原因，确保可追溯其来源版本。

#### FR-DOC-004 停用与删除

- 停用操作立即阻止文档参与新检索，但保留原文件和索引以便恢复。
- 删除操作进入 `DELETING`，立即从检索层过滤并异步物理清理。
- 原文件、内容块、向量、倒排索引、缓存和预览资源均属于删除范围。
- 删除完成后，旧引用可以显示“来源已删除”，但不能继续读取正文。

### 10.4 文档解析与入库任务

#### FR-INGEST-001 异步入库

- 上传完成后创建独立入库任务，立即返回任务编号。
- 入库阶段至少包括：校验、解析、清洗、分块、向量化、索引写入和校验。
- 用户可查看当前阶段、进度、开始时间、耗时和错误。
- 服务重启后任务可继续调度，运行中断的任务可被识别并安全重试。
- 同一文档版本不得有两个任务同时写入线上索引。

#### FR-INGEST-002 文本解析

- 保留标题层级、段落、列表和表格文本的合理阅读顺序。
- PDF 保留原始页码；PPTX 保留幻灯片编号；XLSX 保留工作表名称；EML 保留主题、发件人、收件人和发送时间等基础头信息。
- EML 解析邮件头和正文；支持格式的附件作为关联子文档进入独立入库任务，不支持的附件记录告警并跳过。
- HTML 不抓取外部 URL 或资源，移除脚本、样式和不可见内容后解析正文，禁止通过页面内容发起网络请求。
- XLSX 只读取文件中已保存的单元格值，不执行或重新计算公式；默认处理可见工作表，隐藏工作表记录告警并跳过。
- PPTX 提取幻灯片正文、表格和演讲者备注并保留幻灯片编号；PNG、JPG/JPEG 使用本地 OCR。
- 图片和扫描 PDF 使用本地 OCR 提取中文及混合文本，并记录 OCR 置信度、页码或图片编号。
- OCR 结果低于质量阈值时必须标记为需人工检查，不得直接作为高质量内容静默发布。
- 重复页眉页脚和纯装饰内容不应大量进入索引。
- 解析失败时返回明确错误码，不得生成空索引并标记成功。

#### FR-INGEST-003 清洗规则

- 支持去除多余空白、重复空行和不可见控制字符。
- 保留对语义有用的标题、列表编号、表格行列标识和链接文本。
- 不得执行文档中的脚本、宏、外部命令或嵌入对象。
- 清洗前原文、清洗后文本和规则版本需可追溯。

#### FR-INGEST-004 失败、取消与重试

- 处理中的任务可以申请取消。
- 确定性错误，如格式不支持或文件损坏，不得无限自动重试。
- 临时依赖失败允许有限次数自动重试并采用退避策略。
- 人工重试创建新的执行记录，保留原失败记录。
- 任务失败不得留下可被线上检索命中的半成品索引。

#### FR-INGEST-005 LlamaIndex 使用边界

- 入库工作单元必须使用 LlamaIndex 的本地 Loader、Node Parser、Transform 和 Ingestion Pipeline 组织读取、清洗、分块和 Embedding 转换步骤，不再保留“或等价组件”表述。
- LlamaIndex `Document`、Node 等内部对象必须映射为平台定义的文档、内容块、版本和元数据对象，不能直接作为 HTTP/MCP 对外契约。
- 文档编号、版本号、内容块编号、权限元数据和索引版本由 RAG Base 分配，不能由 LlamaIndex 临时对象决定。
- LlamaIndex 流水线只生成待发布内容块和向量，不得绕过平台索引服务直接把半成品写入生产 Elasticsearch 或 pgvector。
- 在线检索不依赖 LlamaIndex Retriever；Elasticsearch 关键词召回、pgvector 向量召回、权限过滤、融合、Rerank 和追踪由平台检索服务直接编排。
- MVP 仅使用可在私有化环境本地运行的开源组件，不调用 LlamaCloud、LlamaParse 云 API 或外部托管解析服务。

### 10.5 分块管理

#### FR-CHUNK-001 分块策略

MVP 提供：

| 策略 | 适用文档 | 主要规则 |
| --- | --- | --- |
| 通用分块 | 普通文档、网页、Markdown | 按标题、段落和 Token 上限切分 |
| 章节分块 | 制度、手册、长文档 | 尽量保留章节层级和标题上下文 |
| Q&A 分块 | FAQ、问答数据 | 一问一答形成一个语义单元 |
| 表格分块 | CSV、XLSX | 保留表头，并按行组切分 |
| 父子分块 | 需要精准召回和完整上下文的文档 | 子块参与匹配，命中后返回父块 |

#### FR-CHUNK-002 分块参数

- 支持配置目标 Token 数、最大 Token 数、重叠长度和分隔符。
- 分块不得从 Unicode 字符、Markdown 链接或表格单元格中间粗暴截断。
- 子块必须记录父块编号，父块和子块都可追溯到原文位置。
- 修改分块策略需要重新生成内容块和索引，旧索引继续服务直到新版本完整切换。

#### FR-CHUNK-003 内容块结构

每个内容块至少包含：

- `chunk_id`、`knowledge_base_id`、`document_id`、`document_version`；
- 内容文本及 Token 数；
- 原始页码/幻灯片/工作表信息；
- 在原文中的位置信息；
- 标题路径；
- 父块编号（适用时）；
- 业务元数据；
- 权限元数据；
- 启用状态；
- 解析、分块和 Embedding 版本。

#### FR-CHUNK-004 预览与人工干预

- 运营人员可按文档查看全部内容块及对应原文位置。
- 支持编辑内容块文本、补充关键词、修改允许编辑的元数据、启用和停用内容块。
- 编辑已发布内容块时必须创建新的文档草稿版本，不得原地修改线上内容块。
- 编辑正文、关键词或元数据时，从当前发布版本复制内容块形成草稿版本，再在副本上应用修改；不得仅通过重新解析原文件生成该草稿。只对发生变化的内容块重新生成向量，完成 Elasticsearch/pgvector 双索引校验后原子发布，失败时继续使用上一已发布版本。
- 只有替换原文件或修改解析/分块策略时才重新解析和分块；操作前必须提示已有人工修改需要重新合并。
- 内容块启用/停用属于即时运营状态 `chunk_enabled`，审计后立即影响检索且不创建文档内容版本；正文、关键词和元数据修改必须创建新版本。
- 编辑和停用操作保留操作者、时间和变更前后内容。
- 不允许直接在搜索引擎后台修改生产索引绕过业务审计。

### 10.6 索引与模型管理

#### FR-INDEX-001 Embedding 服务

- 平台通过统一模型适配层调用私有化环境内的 `BAAI/bge-m3` 推理服务。
- 支持配置本地服务地址、模型版本、模型文件校验值、向量维度、批次大小、超时、并发限制和计算设备。
- MVP 不提供外部 Embedding API 配置，不得把文档内容、内容块或查询发送到公网模型服务。
- 模型文件可通过受控外网下载，但必须经过来源、版本、许可证和校验值确认后保存到本地；运行时不得静默更新模型。
- 相同文本、模型和标准化规则可复用缓存，但不得跨安全边界泄露原文。
- 模型切换、维度变化或标准化规则变化必须触发索引重建。

#### FR-INDEX-002 索引一致性

- PostgreSQL 保存文档、版本、内容块、任务和发布状态，作为业务事实来源；pgvector 保存内容块向量及其索引。
- Elasticsearch 保存可重建的关键词倒排索引和检索字段，不作为业务事实来源。
- pgvector 向量记录和 Elasticsearch 文档均必须携带已确定的权限元数据，以及参与检索的业务元数据。
- 索引写入采用版本化机制；pgvector 新版本数据与 Elasticsearch 新索引均校验完成后，才统一切换为可检索版本。
- Elasticsearch 使用索引别名或等价机制完成原子切换；pgvector 通过已发布索引版本过滤，禁止半成品向量参与检索。
- `IndexVersion` 必须归属于知识库，知识库只保存一个 `active_index_version`；活动版本切换在数据库事务内完成，ES 与 pgvector 任一侧校验失败都不得切换。
- 提供一致性检查任务，识别 PostgreSQL 业务数据、pgvector 向量和 Elasticsearch 文档之间的缺失、重复、版本不一致和孤儿记录。
- 可以从业务数据和原始文件重建索引。

#### FR-INDEX-003 索引清理

- 文档停用后在线查询通过状态和权限双重过滤，不能仅等待后台删索引。
- 文档删除后清理 pgvector 向量、Elasticsearch 倒排记录和缓存。
- 清理失败进入重试队列并告警。
- 管理员可查看待清理数量，但不得从管理页面读取未授权正文。

### 10.7 检索能力

#### FR-SEARCH-001 检索范围

- 一次请求可检索一个或多个知识库。
- 可进一步限制到指定文档。
- 参与检索的知识库必须使用兼容的查询 Embedding；不兼容时应分别检索并统一融合，或明确拒绝，不能直接混算不同向量空间的得分。
- 只检索 `PUBLISHED` 文档和已启用内容块。
- 检索前由服务端注入固定 `tenant_id`，并完成调用账号和知识库权限过滤；客户端不得指定或切换租户。

#### FR-SEARCH-002 关键词检索

- 使用 Elasticsearch 完成基于词项相关度的召回，适用于产品型号、法规编号、专有名词和精确短语。
- 中文索引使用 IK 分词器：建索引采用 `ik_max_word`，查询采用 `ik_smart`；英文和业务代码保留基础 Token 分析能力。
- 关键词召回默认取前 50 条候选。
- 关键词召回结果保留原始得分和命中高亮信息。
- 用户输入不得被直接拼接为 Elasticsearch 查询语句，所有查询必须通过受控 DSL 模板和参数校验生成。

#### FR-SEARCH-003 向量检索

- 使用平台固定的本地 `BAAI/bge-m3` 对查询生成向量。
- 使用 PostgreSQL/pgvector 完成向量存储、相似度计算和候选召回。
- pgvector 中的向量维度必须与 `BAAI/bge-m3` 的 1024 维输出一致，写入前必须校验维度。
- 文档向量和查询向量写入或检索前进行 L2 归一化，pgvector 使用余弦相似度。
- 向量召回默认取前 50 条候选。
- 返回原始向量相似度。
- 查询向量生成失败时不得伪造向量结果；按 FR-SEARCH-008 根据本次检索模式返回失败或降级结果。

#### FR-SEARCH-004 混合检索与融合

- `KEYWORD` 模式只执行 Elasticsearch 关键词召回；`VECTOR` 模式只执行 pgvector 向量召回；`HYBRID` 模式同时执行两路召回。
- 混合模式同时执行 Elasticsearch 关键词召回和 pgvector 向量召回。
- 混合模式使用 Reciprocal Rank Fusion（RRF）生成统一候选集，默认常量 `k=60`。
- 同一内容块被多路召回时只保留一条，并记录各路得分。
- 最终结果保留 BM25 原始得分、关键词排名、余弦相似度、向量排名、RRF 得分和融合排名，不直接相加不同检索后端的原始得分。
- 多知识库请求按 `retrieval_mode` 对每个知识库执行相应召回；混合模式合并全部排序列表后执行 RRF。候选数、RRF 和最终返回数量使用本次调用实际生效的参数。
- 多知识库传入顺序不得影响最终结果；排序并列时使用稳定的内容块编号作为最终确定顺序。

#### FR-SEARCH-005 重排序

- 调用参数 `rerank` 决定是否启用 Rerank；启用时固定使用私有化环境内的 `BAAI/bge-reranker-v2-m3`。
- Rerank 默认处理当前检索模式候选集的前 50 条，不能对全库逐条调用模型。
- 查询和候选内容块只允许发送到本地 Rerank 推理服务，不得发送到外部模型 API。
- 保留模型原始输出为 `rerank_logit`，使用 Sigmoid 计算 `[0,1]` 区间的 `rerank_score`，并返回重排前后位置。
- 启用 Rerank 时，`rerank_threshold` 默认 `0.50`，只在 Rerank 完成后作用于 `rerank_score`；未启用或降级时不应用该阈值。
- 启用 Rerank 时最终 `score=rerank_score`；未启用或 Rerank 降级时，关键词模式使用关键词得分、向量模式使用向量相似度、混合模式使用 RRF 得分。响应通过 `score_type` 标识实际得分语义。
- Rerank 超时或不可用时返回当前检索模式的召回或融合排序结果，并在响应中明确标记。

#### FR-SEARCH-006 元数据过滤

- 支持按知识库预先声明的业务元数据字段过滤。启用 K12 业务模板时，可使用 `content_type`、`course_id`、`grade_code`、`subject_code`、`campus_id`、`term_code`、`class_type`、`valid_from`、`valid_to`、`sales_stage`、`channel` 和 `tags`。
- MVP 支持等于、不等于、包含、范围、`IN`，以及 `AND`/`OR` 组合。
- 日期和数字必须按实际类型比较，不能统一按字符串比较。
- 服务端必须在 Elasticsearch 和 pgvector 两路召回中应用同一组强制范围与状态条件：`tenant_id`、已授权的 `knowledge_base_id`、当前 `document_version`、当前 `index_version`、`document_status=PUBLISHED` 和 `chunk_enabled=true`；请求限定文档时再校验并应用 `document_id`。
- 当前时间必须满足 `(valid_from IS NULL OR valid_from <= 当前时间)` 且 `(valid_to IS NULL OR valid_to > 当前时间)`；统一使用 UTC，MVP 不提供历史时间点检索例外。
- 权限条件由服务端根据认证身份和授权关系生成，不能被客户端自定义过滤条件覆盖、放宽或删除。
- 业务元数据只用于业务范围筛选，不能替代固定租户、知识库、文档状态等权限判断。
- 多知识库请求中，任一知识库缺少过滤字段或字段类型不兼容时，整次请求返回 `422 FILTER_FIELD_INCOMPATIBLE`，不得静默忽略条件或部分检索。
- 过滤 DSL 最大嵌套深度为 5、最多 20 个叶子条件、单个 `IN` 最多 100 个值、单个字符串值最多 256 个字符；时间值必须为 UTC ISO-8601。无效字段、类型错误或超限应拒绝并返回明确错误。

#### FR-SEARCH-007 结果裁剪与上下文预算

- 调用方可以在 FR-SEARCH-009 规定的范围内设置检索模式、候选数、RRF 常量、Rerank 开关、阈值、`top_n` 和最大总 Token 数；`top_n` 允许 `1～50`，未传入时为 10。
- 结果按最终相关性排序。
- 超过上下文预算时按完整内容块裁剪，不得在未知字符边界截断。
- 父子分块模式命中子块后返回父块，同时保留命中子块信息。
- 相同文档相邻且高度重复的结果可合并或去重，但必须保留全部引用位置。

#### FR-SEARCH-008 空结果和降级

- 无满足阈值的内容块时返回空数组，不生成看似正确的占位知识。
- 响应包含空结果原因，如无命中或全部低于阈值；权限问题统一返回 `403 FORBIDDEN_SCOPE`，不得作为空结果返回或泄露未授权数据存在性。
- 空结果由调用方按自身业务规则处理，RAG Base 不生成替代答案。
- `KEYWORD` 模式下 Elasticsearch 不可用时返回 `503 RETRIEVAL_UNAVAILABLE`；`VECTOR` 模式下 Embedding 服务或 pgvector 不可用时返回该错误。
- `HYBRID` 模式下 Elasticsearch 不可用时降级为向量检索，Embedding 服务或 pgvector 不可用时降级为关键词检索；两条召回链路均不可用时返回 `503 RETRIEVAL_UNAVAILABLE`。
- Rerank 不可用时返回当前召回或融合结果，不以空结果伪装成功。
- 鉴权、权限过滤、活动索引版本或状态过滤异常时禁止降级，必须直接失败。
- 降级成功的响应必须包含 `degraded=true`、`degraded_stage` 和 `degraded_reason`，并写入检索追踪、审计和告警。

#### FR-SEARCH-009 检索调用参数与默认值

HTTP `search` 接口与 MCP `search_knowledge` 工具使用同一组检索调用参数。调用方可以在允许范围内传入参数；未传入时使用平台默认值。

| 参数 | 默认值 | 允许范围 | 说明 |
| --- | --- | --- | --- |
| `retrieval_mode` | `HYBRID` | `KEYWORD`、`VECTOR`、`HYBRID` | 分别表示关键词、向量和混合检索 |
| `keyword_candidate_k` | `50` | `1～200` | 关键词模式和混合模式生效 |
| `vector_candidate_k` | `50` | `1～200` | 向量模式和混合模式生效 |
| `rrf_k` | `60` | `1～200` | 仅混合模式生效 |
| `rerank` | `true` | `true/false` | 是否使用本地 Rerank 模型 |
| `rerank_threshold` | `0.50` | `0～1` | `rerank=true` 时生效 |
| `top_n` | `10` | `1～50` | 最终返回内容块数量 |
| `max_context_tokens` | `8000` | `1000～32000` | 单次返回内容的最大 Token 预算 |

不适用于当前检索模式的参数不参与执行。服务端必须校验参数范围，并在响应和检索追踪中记录实际生效的模式与参数。知识库仅维护解析分块配置和元数据 Schema，不保存独立的在线检索参数。

### 10.8 引用与可追溯性

#### FR-CITE-001 引用信息

每条检索结果至少返回：

- 知识库编号和名称；
- 文档编号、版本和文件名；
- 内容块编号；
- 原始页码、幻灯片编号或工作表名称（可获得时）；
- 标题路径；
- 原文位置或边界框（可获得时）；
- 稳定引用标识 `citation_id`；
- 可授权访问的预览入口，而不是永久公开 URL。

#### FR-CITE-002 引用稳定性

- `citation_id` 必须指向具体文档版本和内容块版本。
- 重新入库产生新版本时，不覆盖历史引用指向。
- 调用方可以使用 `citation_id` 关联检索来源；文档发布新版本后，历史引用只返回文档名称、原版本号和“历史版本不可查看”状态，不返回旧版本正文、内容块文本或预览。
- 用户点击引用时再次执行权限校验。
- 来源被删除后引用显示已删除状态，不返回历史正文。

### 10.9 HTTP 检索 API

#### FR-API-001 统一检索接口

MVP 提供：

`POST /api/v1/retrieval/search`

并提供以下检索辅助只读接口：

- `GET /api/v1/retrieval/knowledge-bases`：返回当前 API 调用账号可检索的知识库；
- `GET /api/v1/retrieval/chunks/{chunk_id}`：返回有权限且属于当前发布版本的内容块及来源定位；
- `GET /api/v1/retrieval/citations/{citation_id}`：当前发布版本返回引用片段和来源信息；历史版本只返回来源标识、原版本号和不可查看状态，不返回旧正文。

上述接口统一使用 API Key 鉴权并校验知识库授权。搜索和内容块详情只允许访问当前发布版本、活动索引版本和已启用内容块；引用详情指向历史版本时只返回来源标识和不可查看状态。无权限或无法确认存在统一返回 `403 FORBIDDEN_SCOPE`。HTTP 与 MCP 共享领域服务和返回模型。

请求核心字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `query` | 是 | 待检索的查询文本 |
| `knowledge_base_ids` | 是 | 目标知识库列表 |
| `document_ids` | 否 | 进一步限定文档 |
| `retrieval_mode` | 否 | `KEYWORD`、`VECTOR`、`HYBRID`，默认 `HYBRID` |
| `keyword_candidate_k` | 否 | 关键词候选数，默认 50，范围 1～200 |
| `vector_candidate_k` | 否 | 向量候选数，默认 50，范围 1～200 |
| `rrf_k` | 否 | 混合检索 RRF 常量，默认 60，范围 1～200 |
| `rerank` | 否 | 是否启用 Rerank，默认 `true` |
| `rerank_threshold` | 否 | Rerank 阈值，默认 0.50，范围 0～1 |
| `top_n` | 否 | 最终返回数量，默认 10，范围 1～50 |
| `metadata_filter` | 否 | 业务元数据过滤条件；不接收权限元数据 |
| `max_context_tokens` | 否 | 返回内容总预算，默认 8000，范围 1000～32000 |
| `request_id` | 是 | 调用方请求编号，用于链路追踪和幂等诊断 |

查询文本最多 4,000 个字符；单次最多传入 20 个知识库 ID 和 100 个文档 ID。HTTP 与 MCP 对上述参数使用相同的默认值、范围和校验规则。

#### FR-API-002 检索响应

响应至少包含：

- `trace_id`、`request_id`；
- 实际检索的知识库、检索模式和生效参数；
- `degraded`、`degraded_stage`、`degraded_reason`；
- 总耗时及主要阶段耗时；
- 结果列表；
- 空结果原因或错误码。

每个结果包含：

- `content`；
- `chunk_id`、`parent_chunk_id`；
- `document_id`、`document_version`、`document_name`；
- `knowledge_base_id`；
- `score`、`score_type`、`keyword_score`、`keyword_rank`、`vector_score`、`vector_rank`、`rrf_score`、`fusion_rank`、`rerank_logit`、`rerank_score`、`rerank_rank`；
- 页码/幻灯片/工作表和标题路径；
- 允许返回的元数据；
- `citation_id` 和受保护的预览信息。

调用方不应解析平台内部日志或搜索引擎响应来判断结果。
`score` 表示最终排序得分：启用 Rerank 且未降级时使用 `rerank_score`；未启用或 Rerank 降级时，分别使用关键词得分、向量相似度或 RRF 得分。`score_type` 对应为 `RERANK`、`KEYWORD`、`VECTOR` 或 `RRF`。

#### FR-API-003 调用约束

- HTTP API 和 MCP Server 统一使用本平台签发的 Bearer API Key；不接入公司 IAM、SSO 或统一服务认证。
- 管理界面仅使用本平台人工账号的登录凭证和登录后访问凭证，不允许使用 API Key 登录。
- 调用方必须设置明确超时；推荐值在试运行性能基线形成后发布，不在 MVP 需求阶段预设固定秒数。
- 检索请求是只读操作，网络重试不得产生业务副作用。
- 平台支持客户端断开后及时取消不再需要的下游模型请求。
- 平台不在检索接口内调用聊天模型生成最终回答。

#### FR-API-004 轻量客户端

- 提供轻量 Python 客户端封装鉴权、超时、错误码和响应模型。
- 客户端核心方法保持简单：`retrieve(query, knowledge_base_ids, filters, options)`。
- 客户端不内置业务框架，不要求调用项目引入额外编排依赖。
- 提供同步和异步调用方式。
- 提供最小接入示例、引用传递示例和空结果处理示例。

#### FR-API-005 接口行为规则

- 接口只返回检索结果，不调用生成模型补写或改写结果内容。
- 调用方不得使用无权限文档编号探测数据是否存在。
- 请求中的任一知识库无权限或无法确认存在时，整次请求返回 `403 FORBIDDEN_SCOPE` 且不执行检索。
- 对外检索中，知识库不存在、已删除、未授权或调用方无法确认存在均使用 `403 FORBIDDEN_SCOPE`；仅内部管理接口在调用方通过认证且具备管理范围时使用 `404 RESOURCE_NOT_FOUND`。
- 无结果、超时和服务不可用使用不同状态和错误码表示。
- 检索内容按数据返回，不解释或执行文档中的指令性文本。
- 同一 `request_id` 和平台 `trace_id` 应能关联完整调用链。

#### FR-API-006 管理接口边界

- 对外仅开放检索 REST API，不将账号、API Key、知识库、授权、文档、导入任务、发布、删除、检索测试和评测管理接口作为外部集成能力。
- 管理功能由管理前端调用私有 REST API 实现；私有接口使用人工账号登录后的访问凭证，不接受 API Key。
- 管理接口必须完整生成独立的内部 OpenAPI 文档，覆盖请求/响应模型、状态变化、错误码和权限要求，供前端联调和自动化测试使用。
- 管理接口仅允许公司内网和管理前端访问，不承诺对外部调用方长期兼容；破坏性变更仍需同步更新前端、内部 OpenAPI 和测试。
- 所有管理写操作仍须执行权限校验、状态机约束和审计记录；重复提交可能产生副作用的操作必须具备幂等保护。

### 10.10 MCP 检索服务

#### FR-MCP-001 MCP 服务与传输

- 平台提供独立 MCP 接入端点，默认路径为 `/mcp`。
- MVP 冻结使用 MCP `2026-07-28` 协议版本和无状态 Streamable HTTP 传输。
- 网关使用与 HTTP API 相同的 Bearer API Key 校验 `Authorization` 请求头；API Key 不进入 MCP 工具参数或协议业务对象。
- MCP `2026-07-28` 不执行 `initialize`、`initialized`，不依赖会话 ID；客户端可直接调用 `tools/list`、`tools/call`，需要能力发现时调用 `server/discover`。
- 网关必须校验 `Mcp-Protocol-Version`、`Mcp-Method`、`Mcp-Name`，并校验请求 `_meta` 中的协议版本、客户端信息和能力声明；MVP 不实现 OAuth。
- 使用支持自定义 API Key 请求头的 LangChain/LangGraph MCP 客户端和 MCP Inspector 完成兼容性验收。
- 不实现新的传统 HTTP+SSE 接口；如未来需要兼容旧客户端，需单独评审。
- 如未来兼容 `2025-11-25` 等旧版 MCP，应使用独立端点和版本协商，不得在 MVP 端点混用生命周期语义。
- MCP 层只负责协议转换，所有检索必须调用与 HTTP API 相同的应用服务。

#### FR-MCP-002 MCP 工具集

MVP 至少提供：

| 工具 | 主要输入 | 主要输出 |
| --- | --- | --- |
| `search_knowledge` | 查询、知识库列表、过滤条件、检索模式与参数、请求编号 | 内容块、得分、元数据、引用、生效参数和追踪编号 |
| `list_knowledge_bases` | 分页、名称筛选 | 当前 API 调用账号有检索权限的知识库 |
| `get_chunk` | 内容块编号或引用编号 | 当前版本返回有权读取的内容块；历史引用只返回来源标识和不可查看状态 |

工具约束：

- 每个工具提供明确名称、用途、输入 JSON Schema、结构化输出 Schema 和错误说明。
- 工具返回机器可读结构化结果，调用方无需从自然语言文本中解析字段。
- `search_knowledge` 与 HTTP 检索接口使用相同参数默认值、权限和排序语义。
- `search_knowledge` 输入 Schema 必须包含 `retrieval_mode`、`keyword_candidate_k`、`vector_candidate_k`、`rrf_k`、`rerank`、`rerank_threshold`、`top_n` 和 `max_context_tokens`；字段默认值与范围以 FR-SEARCH-009 为准。
- `list_knowledge_bases` 只返回当前 API 调用账号已授权的知识库。
- `get_chunk` 必须再次执行权限、文档状态和内容块状态校验；引用指向历史版本时不得返回旧版本正文或预览。
- MVP 不通过 MCP 提供账号、权限、文档上传、删除或索引管理工具。
- 返回内容超过协议或上下文限制时应裁剪到完整内容块，并明确返回截断标志。

#### FR-MCP-003 MCP 错误、限流与追踪

- MCP 鉴权错误、协议错误、参数错误、权限错误和检索错误必须可区分。
- MCP 与 HTTP API 共享 API Key 配额和限流计数，不能通过切换协议绕过限制。
- 工具调用产生 `trace_id`，并接受调用方传入的 `request_id`。
- MCP 访问日志记录工具名、调用账号、知识库、耗时和状态，不记录 API Key 或完整正文。
- 客户端断开或取消时，应尽快取消仍在等待的下游检索或 Rerank 请求。

### 10.11 LangChain 与 LangGraph 接入

#### FR-FRAMEWORK-001 LangChain Retriever

- 提供独立 Python 集成包，不要求调用方自行解析 HTTP/MCP 原始响应。
- 提供符合 LangChain `BaseRetriever` 语义的 `RagBaseRetriever`。
- 支持同步和异步检索，可通过标准 `invoke`/`ainvoke` 调用。
- Retriever 可配置服务地址、API Key、知识库列表、默认过滤条件、检索模式、候选数、RRF、Rerank、阈值、`top_n`、上下文预算、超时和传输方式。
- 默认通过 HTTP API 调用；需要时可以选择 MCP 传输，但返回语义必须一致。
- 每个检索结果转换为 LangChain `Document`：`page_content` 保存内容块文本，`metadata` 保存知识库、文档、版本、页码、块编号、各项得分、引用编号和追踪编号。
- 集成包不得执行 Embedding 或访问搜索引擎，所有检索逻辑保留在 RAG Base 服务端。

#### FR-FRAMEWORK-002 LangGraph 接入

- 提供可直接放入 LangGraph `StateGraph` 的异步检索节点示例或辅助函数。
- 节点输入至少支持查询、知识库列表、过滤条件和检索参数。
- 节点返回可合并到图状态的结构化对象，包含原始 `Document` 列表、引用列表和 `trace_id`。
- 节点不规定业务项目的完整 State Schema、路由逻辑、会话状态或后续处理方式。
- 提供使用 HTTP Retriever 的示例和直接调用 MCP `search_knowledge` 工具的示例。
- 超时、权限失败、无结果和可重试错误必须以明确状态返回或抛出可识别异常。

#### FR-FRAMEWORK-003 版本兼容与交付

- 明确声明 Python、`langchain-core` 和 LangGraph 的支持版本范围。
- LangChain MCP 集成采用当前维护的 `langchain.mcp` 能力，不将已停止维护的 `langchain-mcp-adapters` 作为基础依赖。
- 对声明支持范围的最低版本和最高版本执行自动化兼容性测试。
- 集成包与核心 FastAPI 服务独立发布和版本化，升级调用端依赖不应影响服务端部署。
- 提供安装、配置、同步调用、异步调用、LangGraph 节点和 MCP 调用示例。
- 示例配置只能使用占位密钥，禁止提交真实 API Key。

### 10.12 检索测试与评测

#### FR-EVAL-001 单条检索测试

- 运营人员可在知识库内输入查询并查看各阶段结果。
- 展示关键词召回、向量召回、融合、阈值过滤和 Rerank 前后顺序。
- 展示每个内容块的各项得分、文档、页码、元数据和最终返回原因。
- 可以调整参数进行单次测试，参数只对当前测试生效，不修改其他调用请求的默认值。

#### FR-EVAL-002 评测集

- 评测集由问题、期望命中文档/内容块、可选相关等级和备注组成。
- 支持 CSV 导入和界面维护。
- 评测集需要版本化，禁止直接覆盖已用于发布门禁的版本。
- 评测数据同样受知识库权限控制。
- 技术团队在预发布环境建立独立的“验收知识库”，使用经公司批准且完成脱敏的代表性文档；该知识库与上线后由业务团队创建的生产知识库相互独立。
- MVP 正式验收评测集由技术团队准备，必须包含不少于 100 个真实业务问题，并在上线验收前冻结验收知识库语料、文档版本、问题、期望命中内容块和检索参数集。
- 平台首次上线指标只针对验收知识库；生产业务知识库上线后分别建立自己的评测基线，不反向阻塞平台首次上线。

#### FR-EVAL-003 批量评测

- 支持使用指定检索参数集批量运行评测集。
- MVP 统计 Recall@K、Precision@K、MRR@K、nDCG 和无结果率。
- 记录每次评测的知识库版本、索引版本、模型版本和实际检索参数。
- 支持对两个检索参数集进行结果对比。
- MVP 使用 FR-SEARCH-009 的默认混合检索参数集执行上线验收；门槛固定为 `Recall@10 >= 0.80`、`MRR@10 >= 0.60`，权限泄露用例必须 100% 通过。低于任一门槛时禁止平台首次上线，但不阻止业务文档在测试或已上线环境中发布。

### 10.14 管理与运维

#### FR-ADMIN-001 模型配置

- 管理员可配置本地 Embedding 和 Rerank 推理服务的运行参数，但 MVP 不支持接入任意外部模型供应商。
- Embedding 固定为 `BAAI/bge-m3`，Rerank 固定为 `BAAI/bge-reranker-v2-m3`。
- 管理员仅可配置本地服务地址、超时、并发、批次大小和计算设备；模型名称、版本、文件校验值和向量维度作为只读部署基线展示。
- 上线前提供连接和最小推理测试。
- 已被知识库使用的模型不能直接删除。
- 模型升级必须创建新的索引版本并全量重建；新索引校验并原子切换前继续使用旧模型和旧索引。

#### FR-ADMIN-002 运行概览

管理员可查看：

- 入库任务各状态数量和队列积压；
- 文档数、内容块数、索引大小和存储使用量；
- 检索 QPS、成功率、P50/P95/P99 延迟；
- Embedding、搜索和 Rerank 各阶段耗时及错误率；
- 按 HTTP、MCP 区分的调用量、错误率和延迟；
- 热门知识库和无结果率；
- 节点及依赖服务健康状态。

#### FR-ADMIN-003 故障诊断

- 管理员可通过 `trace_id` 查询一次检索的脱敏链路。
- 默认只展示 HMAC 查询指纹、字符数、标识、得分、耗时和错误，不保存或展示原始查询正文及文档完整正文。
- 查看敏感正文需要额外授权并产生审计日志。
- 支持按错误码、知识库、API 调用账号和时间范围筛选。

| RetrievalParameterSet | 保存检索测试和评测使用的命名参数集，不作为调用方不可覆盖的线上配置 |
| RetrievalTrace | 记录一次检索的参数、阶段和结果摘要 |
| EvaluationSet / Case / Run | 保存评测集、样例及评测执行结果 |
| ApiKey | 保存 API 调用账号的密钥摘要、状态和权限范围 |
| AuditLog | 保存关键管理和数据变更行为 |

### 11.2 数据一致性原则

- 所有核心实体主键统一使用 UUIDv7，由应用生成；PostgreSQL 使用 `UUID`，OpenAPI/MCP 使用 UUID 字符串，Elasticsearch 使用 `keyword`。
- PostgreSQL 是身份、权限、状态、版本、任务和内容块的业务事实来源。
- pgvector 是 PostgreSQL 内的向量扩展，保存可由内容块和固定模型重新生成的向量及向量索引。
- 七牛云对象存储 Kodo 私有空间保存原文件和受保护预览资源；对象键由平台生成，不使用用户文件名作为存储键。
- Elasticsearch 保存可重建的关键词倒排索引，不保存唯一业务事实。
- 缓存只用于性能，不作为权限和发布状态的唯一判断来源。
- 所有派生数据必须能追溯到文档版本、内容块版本、模型版本和配置版本。
- 知识库、文档版本、入库任务和索引版本必须分别定义允许的状态迁移、执行权限、幂等键和并发冲突错误；未列入迁移矩阵的状态变化一律拒绝。

## 12. 非功能需求

### 12.1 性能

| 编号 | 要求 |
| --- | --- |
| NFR-PERF-001 | 使用可复现的数据集分别测试关键词、向量和混合检索，记录 QPS、P50/P95/P99、成功率和资源消耗 |
| NFR-PERF-002 | 分别测试启用与不启用 Rerank 的检索性能，冻结候选数、模型和硬件条件，形成对比基线 |
| NFR-PERF-003 | 对普通管理 API、上传和异步任务分别记录性能，不用异步任务耗时掩盖在线接口问题 |
| NFR-PERF-004 | 检索并发、队列长度、超时和限流阈值必须可配置；超限时明确限流，不得无界堆积请求 |
| NFR-PERF-005 | 文件上传、解析和索引不得一次性将整个大文件加载到应用进程内存 |
| NFR-PERF-006 | 相同检索参数下记录 HTTP 与 MCP 的协议转换耗时差异，并纳入性能基线 |

性能结论必须注明数据规模、查询集、并发量、模型、硬件和索引配置。业务方确认容量和延迟目标前，以上测试用于发现明显性能缺陷和形成扩容依据，不设置数值型上线门槛。

### 12.2 可用性与可靠性

- MVP 不设置数值型月可用性上线门槛；试运行期间分别统计 HTTP、MCP 和核心检索服务可用性，形成后续 SLO 基线。
- HTTP 和 MCP 接入共享核心检索链路，任一协议故障必须可独立识别。
- 检索服务与入库任务隔离，批量入库不得拖垮在线检索。
- 本地 Embedding 与 Rerank 推理服务故障应有超时、隔离、熔断和健康检查，不能无限等待。
- 线上索引切换必须原子化，失败时继续使用上一可用版本。
- 任务和索引操作支持幂等，重复消息不得产生重复可见内容块。
- 定期执行数据库、对象存储和索引的一致性检查。

### 12.3 安全与隐私

- 所有网络通信使用 TLS；内部调用也需处于可信网络或使用服务认证。
- 七牛云 Kodo 必须使用私有空间；原文件和预览资源只允许通过服务端鉴权后的短期有效下载凭证访问，不提供永久公开下载地址。
- 密码、API Key、模型密钥和签名密钥不得明文存储或写日志。
- 密码必须采用行业认可的自适应密码哈希算法并使用独立随机盐；API Key 必须具备足够随机性。
- 数据库、七牛云 Kodo、日志和备份必须启用静态加密；七牛云访问密钥与业务数据分离保存，不得写入前端、代码、镜像或普通应用配置。
- 登录、密码重置、账号禁用、密钥创建和权限变更均需要审计。
- 文档解析在受限环境中执行，禁止宏、脚本和外部命令执行。
- 防范路径穿越、压缩炸弹、恶意文档、SSRF、越权下载和查询注入。
- 文档内容属于不可信输入，平台只解析和索引内容，不执行其中的指令、脚本或外部调用。
- 日志对用户标识、文档内容、密钥和下载地址进行分级与脱敏。
- 检索追踪默认且统一不保存原始查询正文；查询指纹使用独立、可轮换密钥计算 `HMAC-SHA256`，不得使用无密钥哈希；永久保存查询指纹、字符数、调用账号、检索参数、命中文档/块标识、得分、阶段耗时和结果状态。
- 删除流程覆盖原文件、派生文本、内容块、向量、倒排索引、缓存和预览资源。

### 12.4 可观测性

- API 请求、入库任务和检索请求均有全链路追踪编号。
- HTTP 请求与 MCP 工具调用使用统一追踪规范，并标记接入协议、工具名或接口路径。
- 检索追踪记录权限过滤、查询向量生成、关键词召回、向量召回、融合、Rerank 和返回阶段耗时。
- 不记录原始查询正文、完整向量、密钥和大段命中正文。
- 提供 QPS、延迟、错误率、无结果率、降级率、队列长度、索引大小和模型调用指标。
- 对检索错误率升高、延迟超标、入库积压、索引不一致和存储不足告警。

### 12.5 可维护性与兼容性

- 对外检索 REST API 使用版本前缀，破坏性变更升级主版本；管理前端私有 API 不承诺对外兼容。
- FastAPI 请求和响应使用明确的数据模型校验，并分别生成对外检索 OpenAPI 与内部管理 OpenAPI。
- MCP 工具 Schema 与 HTTP 数据模型从同一业务契约映射，禁止长期手工维护不一致字段。
- LangChain/LangGraph 集成包声明兼容版本矩阵并纳入持续集成测试。
- LlamaIndex 依赖版本必须冻结并通过适配层隔离；升级时需回归解析结果、内容块标识、Embedding、索引一致性和检索排序。
- Python、FastAPI、PostgreSQL、pgvector、Elasticsearch、IK、LlamaIndex、BGE 推理服务、MCP SDK、LangChain 和 LangGraph 必须形成经测试的技术版本基线；锁定精确版本、镜像摘要和依赖锁文件，生产禁止使用 `latest`。
- 响应新增字段保持向后兼容；已有字段不得静默改变语义。
- Embedding、Rerank、Elasticsearch、pgvector 和七牛云 Kodo 通过基础设施适配层接入，业务接口不暴露特定厂商响应结构。
- 索引结构升级需提供滚动重建和回滚方案。
- 管理界面支持 Chrome、Edge 和 Safari 最近两个稳定主版本。

### 12.6 容量与保留

- 业务方当前不确认首期文档量、总页数、内容块数、日新增量和峰值检索 QPS，本期暂不据此设定固定容量目标。
- 系统仍须采集文档量、内容块数、日增量、QPS、延迟、索引大小和存储使用量，便于上线后形成真实容量基线。
- 上传大小、批量数量、并发、队列和限流参数必须可配置，不得将临时测试规模写死为系统上限。
- MVP 服务端上限为：查询文本 4,000 字符、单次 20 个知识库 ID、100 个文档 ID、`top_n=50`、每路候选 200、单文件 200 MB、解压后 1 GB；外部请求不能越过上限。
- 原文件、检索追踪和审计日志永久保存，不设置到期时间，也不得因容量压力自动清理。
- “永久保存”指不按时间自动过期；经过授权的文档/知识库显式删除、法律法规要求删除或安全事件处置仍按删除流程执行。
- 文档被显式删除后，检索追踪仅永久保留文档标识、版本、得分、耗时和操作结果等审计信息，不得借此恢复或继续读取已删除正文。
- 审计日志采用防篡改、追加写或等价机制保存，并支持按时间、账号、知识库和操作类型查询。
- 永久数据应支持备份、恢复和分层归档；归档不得破坏权限校验、审计查询和数据完整性。
- MVP 备份恢复目标为 `RPO <= 24 小时`、`RTO <= 8 小时`，至少每季度执行一次恢复演练并记录实际结果。
- 显式删除应立即从活动数据库、对象存储和索引中失效；备份按既定备份生命周期自然过期，恢复时必须应用删除墓碑重新执行清理，防止已删除内容重新上线。
- 容量达到 70%、85%、95% 时产生不同级别告警。
- 不允许通过自动删除仍在发布状态的知识内容解决容量问题。

### 12.7 私有化部署

- 除七牛云 Kodo 对象存储外，系统核心组件部署在公司控制的服务器、虚拟机或容器环境中。
- PostgreSQL/pgvector 与 Elasticsearch 均部署在公司私有化环境中，不使用公网托管检索服务。
- 交付物至少包含版本化应用镜像、依赖清单、配置模板、初始化脚本、升级说明和回滚说明。
- 环境配置、数据库连接、模型地址、存储地址和密钥必须外置，禁止写死在镜像或代码中。
- 上传文档的原文件和受保护预览允许发送至公司七牛云账号下的 Kodo 私有空间；关系数据、解析文本、内容块、向量/倒排索引、查询、日志、密钥和模型输入输出不得默认发送至其他公网服务。
- FastAPI 服务端使用七牛云官方 SDK 通过 HTTPS 上传、读取和删除对象；管理前端不得持有 AccessKey/SecretKey，也不得绕过私有管理 API 直接管理存储空间。
- 七牛云空间必须设置为私有并启用服务端加密；预览和下载由服务端完成权限复核后签发短期有效下载地址。
- Embedding 与 Rerank 推理服务必须部署在公司私有化环境中，不提供外部模型 API 配置入口。
- 文档、内容块、查询和候选结果不得发送给外部 Embedding 或 Rerank 服务。
- 支持在公司网络内配置访问域名、TLS 证书、反向代理和内部 DNS。
- 提供数据库、七牛云对象、索引配置和关键密钥引用的备份恢复方案，并完成恢复演练。
- 恢复演练必须验证删除墓碑、知识库权限、活动索引版本和 API Key 状态不会因恢复而回退。
- 升级前应执行兼容性检查和备份；升级失败可回滚到上一可用版本。
- 部署文档需说明最低资源要求、端口、依赖服务、存储容量、健康检查和启动顺序。
- 私有化环境需要具备受控外网访问能力，不采用完全离线部署。
- 外网访问以出站连接为主，只允许访问经批准的模型文件、镜像、依赖或通知服务域名。
- 模型文件下载完成后在本地固化版本和校验值；生产推理只读取本地模型文件，不依赖公网模型服务可用性。
- 支持通过公司 HTTP/HTTPS 代理访问外网，并可配置域名白名单、超时、重试和并发限制。
- 所有外部服务调用记录目标服务、调用类型、耗时和结果，但不得记录密钥或完整文档正文。
- 外网服务不可用时，平台应明确报错或按已配置策略降级，不得无限等待。
- 其他非模型外部服务是否允许接收业务数据，仍需按具体服务完成数据安全审批。

## 13. 错误码要求

MVP 至少区分：

| HTTP 状态 | 稳定错误码/场景 |
| --- | --- |
| `400/422` | 参数、过滤器、类型或资源上限错误；跨库字段不兼容使用 `FILTER_FIELD_INCOMPATIBLE` |
| `401` | API Key 无效、已禁用、已删除或所属调用账号已禁用 |
| `403` | `FORBIDDEN_SCOPE`：对外检索资源不存在、已删除、无权限、跨知识库或跨文档访问；不返回具体失败资源 |
| `404` | `RESOURCE_NOT_FOUND`：仅用于身份已认证且具备相应管理范围的内部管理 API |
| `409` | 同一版本正在处理、状态迁移非法、配置版本或并发发布冲突 |
| `429` | 并发或频率超过配额 |
| `503` | `RETRIEVAL_UNAVAILABLE` 或其他必需依赖不可用，且无法按既定策略降级 |
| `504` | 在线检索或下游依赖超时 |

入库文件损坏、解析失败、分块失败和索引写入失败应在上述 HTTP 状态下返回独立稳定业务错误码。MCP 错误对象与 HTTP API 共享同一内部错误枚举和可重试语义，不得通过错误差异暴露资源是否存在。

错误响应必须包含 `trace_id`、稳定错误码、简短说明和是否可重试，不返回内部堆栈、服务器路径或密钥。

## 14. 核心验收场景

### AC-001 文档入库与发布

1. 运营人员创建知识库，查看固定 Embedding 信息并配置通用分块；
2. 按《支持格式矩阵》逐类上传 PDF、DOCX、XLSX、PPTX、TXT、MD、HTML、CSV、JSON、EML、PNG、JPG/JPEG 代表性文件；
3. 系统完成中文解析或 OCR、分块、向量化和索引；
4. 运营人员可以查看内容块及原始页码；
5. 发布前在线接口检索不到，发布后可以检索；
6. 每条结果包含文档版本、页码、内容块和引用标识。
7. EML 附件、HTML 外链隔离、XLSX 公式/隐藏表、PPTX 备注和图片 OCR 按格式矩阵的黄金样例验证；页数、工作表、单元格、附件和解压大小超限时返回稳定错误码。

### AC-002 检索 API 真实接入

1. 真实业务调用方使用 API Key 调用检索接口；
2. API Key 仅能访问明确授权的知识库；
3. RAG Base 返回相关内容块、各阶段得分和引用；
4. 无结果时返回空数组和明确原因，不生成补充答案；
5. 引用入口可在权限校验后查看对应来源；
6. 可通过同一 `request_id`/`trace_id` 串联调用方和 RAG Base 日志。
7. HTTP 的知识库列表、搜索、内容块详情和引用详情与 MCP 对应工具返回一致的权限结果和来源语义。

### AC-003 权限隔离

1. 平台管理员使用唯一邮箱创建独立人工账号，并创建 API 调用账号，不依赖外部账号系统；
2. API 调用账号只有知识库 A 的权限；
3. 同时请求 A、B 时，整次请求返回 `403 FORBIDDEN_SCOPE` 且不执行检索；
4. 修改知识库编号、文档编号或过滤条件不能访问 B；
5. 错误响应不泄露 B 是否存在；
6. 禁用 API 调用账号或撤销知识库权限后，新请求在承诺时间内被拒绝；
7. 人工账号和 API 调用账号的授权变更均可通过审计日志追踪。
8. 不存在用户组或组织继承关系时，账号只能访问授权记录中直接关联的知识库。
9. API Key 不因创建时间自动过期；主动禁用、删除或禁用所属调用账号后立即失效。

### AC-004 三种检索模式与重排序

1. 测试问题包含产品型号和语义描述；
2. 分别使用 `KEYWORD`、`VECTOR`、`HYBRID` 调用 HTTP API 和 MCP，系统按指定模式执行检索；
3. 未传检索参数时使用 FR-SEARCH-009 默认值，传入合法参数时按调用值执行，越界参数被拒绝；
4. `top_n` 分别使用 1、10、50 完成验证，0 和 51 被拒绝；
5. 混合模式使用 RRF 完成融合，相同块正确去重，各阶段得分可查看；
6. `rerank=true` 时执行本地重排序，`rerank=false` 时直接返回对应模式的召回或融合结果；
7. 多知识库传入顺序变化不影响结果；
8. 各检索模式的依赖故障按 FR-SEARCH-008 返回降级结果或 `503 RETRIEVAL_UNAVAILABLE`。

### AC-005 元数据过滤

1. 知识库启用 K12 业务元数据模板，文档配置课程、年级、学科、校区、学期、班型、内容类型、有效期、销售阶段、渠道和标签；
2. 调用方按授权知识库提交业务过滤条件，能够检索对应课程、班期、价格或销售话术；
3. Elasticsearch 与 pgvector 返回结果均满足相同的固定 `tenant_id`、知识库、发布版本、索引版本、文档状态和内容块状态过滤；
4. `valid_from`、`valid_to` 均为空时内容正常参与检索；设置后按 UTC 左闭右开区间判断，未生效或已到 `valid_to` 的内容不参与检索；
5. 客户端提交权限字段、试图覆盖权限条件或使用未声明字段时，请求被拒绝；
6. 类型错误、过滤深度/数量超限或跨知识库字段不兼容时被拒绝并返回明确错误；
7. 验证元数据字段新增、停用、类型迁移、索引重建和文档到内容块继承规则在 ES 与 pgvector 两侧一致。

### AC-006 文档更新

1. 已发布文档 V1 正常参与检索；
2. 上传 V2 并处理时，线上继续使用 V1；
3. 发布 V2 后，新请求只返回 V2；
4. 切换失败时仍使用 V1；
5. 历史追踪仍能识别当时命中的 V1 内容块。
6. 编辑已发布内容块时生成新的文档草稿版本，经双索引校验和原子发布后才影响新检索；编辑失败不影响当前发布版本。
7. 人工编辑在发布和服务重启后仍保留，历史版本不被覆盖；内容块停用立即生效，重新启用后恢复检索。
8. V2 发布后访问 V1 的 `citation_id`，只返回 V1 来源标识和“历史版本不可查看”状态，不返回 V1 正文、内容块或预览。

### AC-007 文档删除

1. 删除请求提交后文档立即不再参与新检索；
2. 后台完成原文件、内容块、向量、倒排索引和缓存清理；
3. 清理失败能够重试和告警；
4. 已有引用只显示来源已删除，不返回正文；
5. 数据库和索引一致性检查无孤儿记录。

### AC-008 检索评测

1. 技术团队使用公司批准且完成脱敏的代表性文档建立独立验收知识库，并冻结语料、文档版本、检索参数集及不少于 100 个真实问题和期望命中；
2. 分别运行两个检索参数集；
3. 系统计算 Recall@K、Precision@K、MRR、nDCG 和无结果率；
4. 结果记录知识库、索引、模型和实际检索参数；
5. 使用 FR-SEARCH-009 默认混合检索参数集达到 `Recall@10 >= 0.80`、`MRR@10 >= 0.60`，且权限泄露用例 100% 通过后才允许平台首次上线；
6. 技术团队复核评测数据、执行过程和指标结果，并给出最终验收结论。

### AC-009 故障恢复

1. 入库过程中工作节点异常退出；
2. 任务不会永久停留在处理中；
3. 重试不生成重复可见内容块；
4. 半成品索引不参与检索；
5. 在线检索继续使用上一可用索引版本。

### AC-010 MCP 检索

1. 支持自定义 Bearer API Key 请求头的 LangChain/LangGraph MCP 客户端和 MCP Inspector 按 `2026-07-28` 协议，通过无状态 Streamable HTTP 在不执行 `initialize/initialized`、不维护会话 ID 的条件下完成 `server/discover` 或直接工具发现；
2. 使用 API Key 调用 `list_knowledge_bases` 时只返回已授权知识库；
3. 调用 `search_knowledge` 时可传入三种检索模式及 FR-SEARCH-009 定义的参数；未传参数时使用默认值，并返回结构化内容块、实际生效参数、得分、引用和 `trace_id`；
4. 使用相同账号和参数调用 HTTP API 与 MCP 时，结果排序和引用语义一致；
5. 无效密钥、越权知识库、错误参数和检索超时返回可区分错误；
6. MCP 无法绕过 HTTP 侧的权限、限流和审计规则。

### AC-011 LangChain/LangGraph 接入

1. LangChain 项目使用 `RagBaseRetriever.invoke` 和 `ainvoke` 获得 `Document` 列表；
2. `Document.page_content` 为内容块文本，`metadata` 包含来源、得分、引用和追踪信息；
3. LangGraph 示例节点可以把检索结果写入图状态，不强制修改业务项目的完整 State Schema；
4. LangGraph 可以选择 HTTP Retriever 或 MCP `search_knowledge` 工具完成同一查询；
5. 超时、无结果、权限错误和服务不可用均可被调用项目明确处理；
6. 声明支持的 LangChain/LangGraph 最低与最高版本均通过自动化测试。

### AC-012 私有化部署

1. 使用正式交付镜像和配置模板在公司环境完成全新部署；
2. PostgreSQL/pgvector、Elasticsearch、模型服务和密钥指向公司控制的私有资源；原文件及受保护预览指向公司七牛云账号下的 Kodo 私有空间；
3. Embedding 与 Rerank 均使用本地模型服务，网络审计确认系统不会向公网模型服务发送文档、查询和检索结果；
4. 健康检查可以识别 FastAPI、任务执行单元、PostgreSQL/pgvector、Elasticsearch、对象存储和模型服务状态；
5. 完成一次备份、故障清空和恢复演练，恢复后账号、知识库、文档和索引可用；
6. 模拟升级失败后可以回滚到上一可用版本；
7. 系统可通过公司代理访问批准的外部服务，未批准目标被阻止并产生审计记录；
8. 未配置公网入口时，外网无法直接访问平台服务。
9. 恢复结果达到 `RPO <= 24 小时`、`RTO <= 8 小时`，已删除内容经删除墓碑处理后不会重新上线。

## 17. 风险与已确认事项

### 17.1 主要风险

| 风险 | 影响 | 需求侧措施 |
| --- | --- | --- |
| 只重视模型、不建设评测集 | 无法判断升级是否有效 | MVP 必须有版本化检索评测集 |
| 文档质量和分块质量差 | 召回效果上限低 | 提供预览、人工干预和分阶段追踪 |
| 不同知识库混用不同向量空间 | 得分不可比较 | 限制同库模型，跨库分路检索后融合 |
| API Key 授权范围过大 | 调用方越权读取知识 | 最小权限授权、范围校验、主动禁用和人工轮换 |
| 删除数据库记录但索引残留 | 敏感内容继续被检索 | 状态过滤、异步清理和一致性巡检 |
| 文档中包含恶意指令或脚本 | 下游误执行或平台受攻击 | 平台不执行内容，解析环境隔离并保留来源类型 |
| Rerank 或 Embedding 服务不稳定 | 延迟上升或检索失败 | 超时、熔断、明确降级和监控 |
| 范围扩张到聊天和答案生成 | RAG 核心能力延期 | 坚持数据入库、检索和评测边界 |

### 17.2 已确认事项

1. 首批调用项目使用 Python、LangChain 和 LangGraph。
2. 调用项目可以选择 HTTP API 或 MCP 调用知识库。
3. RAG Base 后端采用 FastAPI。
4. 平台使用独立账号体系：人工访问使用本平台管理的邮箱和密码凭证；HTTP API 与 MCP 使用本平台管理的 API 调用账号/API Key；不接入公司 IAM、SSO 或统一服务认证。
5. 人工账号使用邮箱作为唯一登录名。
6. FastAPI、任务执行单元、PostgreSQL/pgvector、Elasticsearch 和模型服务采用公司环境内私有化部署；上传文档原文件和受保护预览使用公司七牛云账号下的 Kodo 私有空间。
7. 私有化环境需要受控访问外网，不采用完全离线运行。
8. Embedding 使用 `BAAI/bge-m3`，Rerank 使用 `BAAI/bge-reranker-v2-m3`，两者均在私有化环境本地部署，不调用外部模型推理服务。
9. 全文搜索引擎采用 Elasticsearch，向量库采用 PostgreSQL 的 pgvector 扩展。
10. 课程、年级、校区、学期等 K12 字段作为可选业务元数据模板提供，不要求所有知识库使用；权限元数据采用 FR-DOC-002 定义的固定字段，`security_level` 和 `department_ids` 移出 MVP。
11. 初始平台管理员账号由业务团队指定人员保管。
12. 平台上线后由各业务团队自行创建和维护知识库，不预置固定首批业务知识库；知识库主要语言为中文。
13. MVP 固定支持 PDF、DOCX、XLSX、PPTX、TXT、MD、HTML、CSV、JSON、EML、PNG、JPG/JPEG，不再承诺覆盖 RAGFlow 的全部格式；其他格式、音频和视频移至后续版本。
14. 技术团队使用经批准并脱敏的代表性文档建立独立验收知识库，组织编制并验收不少于 100 个真实问题；门槛为 `Recall@10 >= 0.80`、`MRR@10 >= 0.60`，权限泄露用例 100% 通过。未达标时禁止平台首次上线，不阻止测试环境或已上线环境中的业务文档发布；生产知识库上线后分别建立自身基线。
15. 业务方暂不确认文档规模、内容块数、日增量、峰值 QPS、延迟和可用性目标；MVP 先保证功能完整并形成可复现基线，不设置数值型性能或可用性上线门槛。
16. MVP 只支持人工账号/API 调用账号与知识库直接授权，不支持用户组批量授权或组织层级继承授权。
17. 原文件、检索追踪和审计日志永久保存，不设置基于时间的自动清理策略；检索追踪默认不保存原始查询正文，只永久保存使用独立密钥计算的 `HMAC-SHA256` 查询指纹、字符数、调用账号、参数、命中标识、得分、耗时和状态；显式授权删除及法律法规要求除外。
18. 内部仅使用 LlamaIndex Loader、Node Parser、Transform 和 Ingestion Pipeline 编排入库流程；在线检索由平台直接编排，外部系统继续使用 LangChain/LangGraph，通过 HTTP API 或 MCP 调用。
19. MVP 采用单租户模式，不提供租户创建、切换、租户管理员或租户停用功能；`tenant_id` 仅作为服务端生成的固定内部隔离字段保留，调用方不得传入或修改。
20. MCP 冻结采用 `2026-07-28` 协议和无状态 Streamable HTTP，不执行 `initialize/initialized` 且不维护会话 ID；由网关校验 Bearer API Key、MCP 请求头和 `_meta`，MVP 不实现 OAuth。
21. HTTP 与 MCP 同时开放关键词、向量、混合三种检索模式；未传参数时默认使用混合检索、双路各 50 条候选、`rrf_k=60`、启用 Rerank、阈值 0.50、`top_n=10` 和 `max_context_tokens=8000`。
22. 编辑已发布内容块时复制当前发布版本形成草稿并保留人工修改，经 Elasticsearch/pgvector 双索引校验后原子发布；内容块启用/停用立即生效且不创建内容版本。
23. 对外仅开放检索 REST API；管理接口作为管理前端私有接口实现，但必须生成完整的内部 OpenAPI。
24. 多知识库请求中只要存在无权限或无法确认存在的知识库，整次请求返回 `403 FORBIDDEN_SCOPE`，不允许部分成功。
25. 所有核心实体主键统一使用 UUIDv7；`valid_from`、`valid_to` 均可空，按 UTC 左闭右开区间判断，MVP 不提供历史时间点检索。
26. API Key 不设置过期时间并永久有效，直至被主动禁用、删除或所属 API 调用账号被禁用；平台支持无停机人工轮换，但不得按存续时间自动失效。
27. 对外检索 REST API 包含知识库列表、搜索、内容块详情和引用详情；四项能力与 MCP 共享领域服务、权限和返回语义。
28. HTTP `search` 与 MCP `search_knowledge` 使用相同的检索调用参数；调用方可以在 FR-SEARCH-009 规定范围内传入参数，`top_n` 支持 1～50，未传入时使用平台默认值。
29. 知识库、文档版本和索引版本采用本说明书定义的状态机；同一文档最多一个发布版本，每个知识库最多一个活动索引版本，双索引校验后原子切换。
30. 全局角色仅为 `PLATFORM_ADMIN`、`ACCOUNT_ADMIN`、`USER`；知识库能力使用 `MANAGE`、`EDIT`、`RETRIEVE`、`EVALUATE` 直接授权，平台角色不自动获得知识正文访问权。
31. 对外检索中不存在、已删除和无权限资源统一返回 `403 FORBIDDEN_SCOPE`；内部管理接口在认证且具备管理范围时可以返回 `404 RESOURCE_NOT_FOUND`。
32. 最终响应使用 `score_type` 区分 Rerank、关键词、向量和 RRF 得分，调用方不得将不同类型得分直接比较。
33. 单路检索模式的必需召回服务不可用时返回 `503 RETRIEVAL_UNAVAILABLE`；混合模式允许在单路故障时降级为另一条召回链路；Rerank 故障时返回当前召回或融合结果，权限和版本错误禁止降级。
34. 元数据 Schema 版本化；索引字段类型不可原地修改，文档元数据默认继承到内容块；跨库过滤字段不兼容返回 `422 FILTER_FIELD_INCOMPATIBLE`，过滤 DSL 执行固定复杂度限制。
35. EML、HTML、XLSX、PPTX 和图片解析采用本说明书确定的本地、安全解析规则，并执行页数、工作表、单元格、附件和解压大小上限。
36. 开发前冻结全部核心依赖精确版本、镜像摘要和锁文件，IK 与 Elasticsearch 严格匹配；LangChain 使用当前维护的 MCP 能力。
37. 数据库存储、对象存储、日志和备份启用静态加密；MVP 默认资源上限、`RPO <= 24 小时`、`RTO <= 8 小时` 和删除墓碑恢复规则按本说明书执行。
38. 文档发布新版本后，历史 `citation_id` 只保留来源关联和版本状态，不允许查看旧版本正文、内容块文本或预览。
