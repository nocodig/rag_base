## 3. 建设目标确认

1. 建立统一的知识库、文档、版本、元数据和权限管理能力。
2. 建立解析、清洗、分块、Embedding、双索引构建和原子发布能力。
3. 同时提供关键词、向量和混合三种检索模式，并支持元数据过滤、可选 Rerank 和降级处理。
4. 上层应用可通过 HTTP 或 MCP 检索一个或多个已授权知识库。
5. 每条有效检索结果均可追溯到知识库、文档版本、页码或原文位置及内容块。
6. 文档更新、停用和删除能够正确反映到新检索请求中，不返回旧版本或已删除正文。
7. 建立可重复执行的检索测试、离线评测、调用追踪和故障诊断能力。
8. 至少一个真实业务调用方在测试环境完成端到端接入。

### 8.2 质量与上线硬门槛

- 使用公司批准且完成脱敏的代表性文档建立独立验收知识库；
- 冻结语料、文档版本、检索参数集及不少于 100 个真实问题和期望命中；
- 默认混合检索参数集达到 Recall@10 ≥ 0.80、MRR@10 ≥ 0.60；
- 权限泄露用例 100% 通过；
- 任一指标不达标时，禁止平台首次上线；
- 测试环境验证及已上线环境中的业务文档发布不受该首次上线门禁反向限制。

### 8.3 上线前必须完成

## 10. 暂不设定数值目标的事项

业务方当前暂不确认以下数值：

- 首期文档量、总页数和内容块数；
- 日新增文档量；
- 峰值检索 QPS；
- P95/P99 延迟目标；
- 数值型月可用性目标。

处理原则：MVP 先保证功能闭环和质量门槛，完成可复现的性能、容量及可用性基线测试。上述数值暂不作为首次上线阻断条件，待真实运行数据形成后另行确认 SLO 和扩容目标。

## 11. 主要风险确认

| 风险 | 已确认控制措施 |
| --- | --- |
| 无评测集导致效果无法判断 | 建立版本化评测集和上线质量门禁 |
| 文档质量或分块质量低 | 提供预览、人工干预、OCR 质量标记和分阶段追踪 |
| 不同向量空间得分混用 | 同库统一模型；不兼容知识库分路检索后融合或明确拒绝 |
| API Key 授权范围过大 | 最小权限、范围交集校验、主动禁用和无停机轮换 |
| 删除后索引残留 | 状态过滤、异步清理、重试告警和一致性巡检 |
| 恶意文档触发执行或外部访问 | 隔离解析，禁止脚本、宏、命令和 HTML 外部资源请求 |
| 模型或检索服务故障 | 超时、熔断、健康检查、明确降级和监控告警 |
| 七牛云不可用或访问密钥泄露 | 上传/预览超时与重试、私有空间、最小权限密钥、密钥隔离与轮换、访问审计 |
| 范围扩张到聊天和答案生成 | 严格保持入库、检索、引用和评测的平台边界 |
